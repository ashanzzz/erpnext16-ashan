# 祺富外部工资导入 V3 与员工薪酬母表重构说明

## 1. 本次目标

本次改造把外部工资导入从固定列号解析改为语义字段解析，并把员工身份与退休规则从页面代码中拆成独立服务。预检与正式导入使用同一个解析器，直接 DocType 保存、工作台 API 和后续 AI 辅助写入也共享同一套身份与退休校验。

## 3. 已兼容的主表语义字段

解析器不再使用容易误判的子字符串包含规则。所有关键字段使用精确别名映射。

- 身份与源表信息：编号、工号、姓名、入职日期、本月日期、入职时间。
- 工时工资：作业天数、作业小时、天工资、小时工资、全勤费。
- 加班与国勤：加班、加班小时、加班费、加班/抛光、国勤(天)、国勤天数、国勤、国勤工资。
- 绩效与扣款：抛光、达标率、达标工资、扣除。
- 历史金额：应付工资、已发工资、实发工资。
- 其他：是否社保、签字、备考/备注、100/50/10/5/1 元现金张数。
- 补贴区：职位补贴/岗位津贴、房补/车补/房车补、合计。

无法识别的新列不会参与计算，但每一行的所有原始单元格都会进入 `source_raw_json`。补贴表原始值也一并写入该快照。这样将来增加字段别名后，仍能回溯历史导入内容。原始 Excel 文件本身继续作为结算附件归档，并记录 SHA256。

## 4. 导入流程

1. 扫描全部工作表和前 30 行，寻找最可信的工资主表。
2. 根据精确语义别名建立标准字段映射并识别模板代际。
3. 查找主表下方或其他工作表中的补贴表。
4. 生成标准化行，同时保存所有源列原始快照。
5. 对主表实发、补贴、总计做金额勾稽。大于 1 元的异常阻止正式导入，小额历史舍入差只提示。
6. 用员工母表进行匹配。顺序为真实工号、当前姓名、人工维护的外部姓名别名、唯一一字差异。模糊匹配会记录方式和置信度。
7. 任何未匹配人员或一人多行冲突都会阻止正式导入，避免错发。
8. 标准字段写入月度薪资明细，历史源字段写入审计字段。
9. 预检和正式导入共用同一解析服务，避免两套逻辑产生不同结果。

当前文件格式支持 `.xlsx` 和 `.xlsm`。旧二进制 `.xls` 仍要求先另存为 `.xlsx`，这样可以避免额外引入旧格式解析依赖。

## 5. 员工薪酬档案的新结构

员工母表新增或重构以下字段。

- 证件类型：居民身份证、护照、港澳台证件、其他证件。
- 证件号码。居民身份证自动校验，并自动识别出生日期和性别。历史 15 位身份证兼容读取，但提示后续更新。
- 年龄。动态按所选账期计算。
- 性别。居民身份证自动识别，其他证件人工维护。
- 出生日期。居民身份证自动识别，其他证件人工维护。
- 退休类别：男职工原 60 岁、女职工原 55 岁、女职工原 50 岁、特殊政策/人工确认。
- 退休年龄(原)、退休年龄(延)、原退休月份、延迟后法定退休月份、政策版本。
- 外部工资表姓名别名。用于历史错别字、曾用字和称谓兼容。
- 房/车补。补齐此前界面与 DocType 不一致的问题。

女职工原 50 岁还是原 55 岁属于人事政策属性。系统不会仅根据岗位名称自动写成权威结论。界面必须由人事确认一次。

## 6. 中国退休政策引擎

政策引擎为 `retirement_policy_service.py`，当前版本 `CN-RETIRE-2025-V1`。页面、API 和 DocType 直接保存都调用同一服务。

- 男职工原 60 岁，从 2025 年起每 4 个出生月份延迟 1 个月，逐步到 63 岁。
- 原 55 岁女职工同样每 4 个出生月份延迟 1 个月，逐步到 58 岁。
- 原 50 岁女职工每 2 个出生月份延迟 1 个月，逐步到 55 岁。
- 分别计算原年龄到龄月份和延迟后法定到龄月份。两者都支持提前 1 个月预警。
- 计算最早弹性提前退休月份。最多提前 3 年，同时不得低于原法定退休年龄。
- 计算最晚弹性延迟退休月份。一般最多延迟 3 年。
- 计算弹性提前退休书面告知月份。一般至少提前 3 个月。
- 计算退休年份对应的最低养老保险缴费年限门槛。2030 年起每年增加 6 个月，直到 20 年。

系统只计算年龄和法定门槛，不自动认定员工实际养老保险缴费年限是否满足。该项需要后续接入社保历史数据才能形成最终资格判断。

## 7. UI 设计

员工母表主表扩展为身份、退休、岗位、薪资和社保基础信息的一体化列表。顶部增加原退休预警、延迟退休预警和退休类别待确认数量。

新增/修改员工弹窗分为身份退休、岗位用工、薪资津贴、专项附加扣除四个区域。居民身份证模式下出生日期和性别只读并自动识别。护照等证件则开放手工输入。标准退休类别的退休年龄由政策引擎只读生成，只有特殊政策类别允许人工维护年龄。

外部工资导入预检会显示检测账期、模板结构、兼容度、母表匹配人数、模糊匹配人数、未匹配人员和金额诊断。账期不匹配或存在未匹配人员时禁止点击正式导入。

## 8. 扩展原则

- 新 Excel 模板优先只增加 `FIELD_ALIASES` 或 `ALLOWANCE_ALIASES`，不修改工资核算主逻辑。
- 新退休政策优先修改独立政策服务，不把公式散落到 JS。
- 所有 AI 或外部 API 写员工母表时仍会触发 DocType `validate()`，因此不能绕过身份证和退休规则。
- 计算字段尽量动态生成，不把预警状态长期固化，避免月份变化后产生陈旧状态。
- 源数据和标准数据并存，便于追溯、重算和后续字段升级。
