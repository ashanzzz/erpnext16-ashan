物料申请工作台 (desk/material-request-workbench) 表头与表格架构缺陷全景诊断报告

基于《ERPNext 16 全局开发哲学》与 2026-10-19「阿闪·黑律工规体」最高铁律标准对比

为什么当前「单号视图 / 明细视图」与「已选 0 单」下方的表头让人感觉“没解决”？（六大核心病灶）

病灶 1 · 严重违规
列竖线（列线）几近隐形缺失
表头与表体单元格写死了 border-right: 1px solid #f1f5f9;。颜色浅至几近透明，导致数据纵向串行，严重违反 2026-10-19 全闭合列竖线铁律。
病灶 2 · 排版错位
表头靠左 vs 表体靠右严重错位
表头 申请总数、总金额、价格 等默认全靠左，而表体数值严格靠右，表头与表体上下错位脱节，缺乏等宽排版。
病灶 3 · 平账脱轨
末行合计行 (tfoot) 投影平账脱轨
单号视图中跨列未严格对齐；明细视图中末尾【备注】列下方被截断悬空，未实现四柱守恒垂直 1:1 投影闭环。
病灶 4 · 尺度违规
表头字号 (11px) 与行高写死
CSS 中写死 font-size: 11px; height: 38px;，脱离了全局 --ashan-table-cell-font-size: 13px 与 --ashan-table-header-height: 40px 调度矩阵。
病灶 5 · 视觉冗余
控制栏与表头割裂、按钮重复堆砌
页面右上角已有官方黑【新建物料申请单】，控制栏右侧又重复堆叠蓝色按钮；【已选 0 单】未形成稳态工规胶囊。
病灶 6 · 切换晃动
双视图切换造成剧烈横向抖动 (Jitter)
单号视图 (8列) 与明细视图 (12列) 缺乏固定语义化列宽约束，导致切换视图时表格宽度和列位剧烈震颤。
