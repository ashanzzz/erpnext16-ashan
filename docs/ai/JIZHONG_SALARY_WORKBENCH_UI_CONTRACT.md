# 吉众薪酬工作台 UI 与字体契约

更新日期：2026-09-18

## 1. 范围

本契约仅适用于吉众人事薪酬工作台。

页面所有者：

- `ashan_cn_procurement/ashan_cn_procurement/ashan_cn_procurement/page/jizhong_hr_salary_workbench/jizhong_hr_salary_workbench.js`
- `ashan_cn_procurement/ashan_cn_procurement/ashan_cn_procurement/page/jizhong_hr_salary_workbench/jizhong_hr_salary_workbench.css`

不要创建第二套吉众薪酬工作台、字体系统、选择列或参数调整 API。

## 2. 字体基准

字体基准来自 2026-09-17 对部署中库存台账工作台的实际浏览器检查。

库存台账的计算后样式：

| 对象 | 字号 |
|---|---:|
| 页面主标题 | 20px |
| 表头 | 12px |
| 表格明细 | 13px |

吉众工作台必须使用相同的字号层级。

唯一可编辑的吉众字体设置位于页面 CSS 根选择器：

```css
.ashan-jizhong-workbench {
    --jz-font-page-title: 20px;
    --jz-font-section-title: 16px;
    --jz-font-toolbar: 12px;
    --jz-font-table-header: 12px;
    --jz-font-table-body: 13px;
    --jz-font-table-meta: 12px;
    --jz-font-kpi-value: 20px;
}
```

以后调整吉众字体时，只修改这一组 token。

不要在页面局部再次写 10.5px、11px、13.5px 或 14px 覆盖表格字号。

## 3. 表格规范

### 表头

- 表头必须使用 `--jz-font-table-header`。
- 表头必须使用 700 字重。
- 表头使用 `#334155`。
- 表头行高使用 `--jz-line-table-header`。

### 明细

- 所有普通明细单元格必须使用 `--jz-font-table-body`。
- 金额和数量必须使用等宽数字与右对齐。
- 工号和身份证号可使用等宽字体，但字号仍为 `--jz-font-table-body`。
- 基数来源、策略说明和状态辅助文案使用 `--jz-font-table-meta`。

### 选择列

员工薪酬档案的人员选择框必须放在序号左侧。

冻结列顺序固定：

| 列 | 左侧偏移 | 宽度 |
|---|---:|---:|
| 人员选择框 | 0px | 40px |
| 序号 | 40px | 52px |
| 工号 | 92px | 82px |
| 姓名 | 174px | 112px |

不要改变上述偏移而不同时调整 CSS、表头、表体与合计行。

## 4. 参数调整

员工必须先通过序号左侧的选择框勾选。

勾选后，工具栏显示“调整薪酬参数”动作与已选人数。

单人模式预填当前值。

多人模式统一覆盖所选员工的同一参数。

当前允许调整：

1. 基本工资
2. 绩效奖金
3. 职位津贴
4. 基本补贴
5. 餐补单价
6. 税后固定工资（元/月）
7. 计薪方式（税前动态工资 / 税后固定工资）
8. 用工性质
9. 在职状态
10. 社险申报基数方式
11. 自定义社险基数
12. 公积金申报基数方式
13. 自定义公积金基数
14. 公积金长期缴纳策略

### 计薪方式与税后固定工资语义标准

1. **规范命名**：
   - 显式计薪方式：`税后固定工资`（旧称 `税后管理工资` 仅保留兼容别名支持）。
   - 固定月度净发目标参数：`税后固定工资（元/月）`（旧称 `实发约定净薪`）。
2. **向后兼容性保证**：
   - 历史导入/底层数据库存储的历史别名 `税后管理工资` 保持完全兼容，不执行破坏性数据库清洗。
   - 所有服务层读取（`get_jizhong_payroll_overview`、`get_jizhong_employee_profiles`、`get_jizhong_history_records`）与页面 UI 展示，统一规范化转换为标准 `税后固定工资` 呈现。
   - 考勤免打卡判定依据使用 `is_jizhong_fixed_net_salary_mode` 谓词，旧档案与新档案同等享受免考勤规则。
3. **闭式反推守恒平账不变式（Final-Net Equality Invariant）**：
   - 对于 `税后固定工资` 模式，算薪引擎通过 1:1 VBA 闭式反推税前应发 `gross_salary` 与当月个税 `tax_amount`。
   - 必须确保最终计算所得实发工资 `net_salary` 分毫不差严格等于员工设定的 `fixed_salary`（精确到分：`net_salary == fixed_salary`）。若出现任何微小浮点偏差，系统自动做分级校准并严格断言；若校验不通过则阻断计算，绝不产生账实不符。

涉及社保或公积金自定义基数时，必须同步写入对应的“自定义”申报基数方式。

涉及最低缴费基数时，必须清空对应自定义金额。

公积金策略写入服务端前必须转换为服务端标准值：

| 页面值 | 服务端值 |
|---|---|
| 季度初规则 | 跟随公司规则 |
| 每月正常缴纳 | 固定缴纳 |
| 不缴纳 | 固定停缴 |

## 5. 社会保险与住房公积金信息层级

社会保险和住房公积金的政策参数属于核对参考信息，不是页面的长期主操作区。

- “本月政策参数”默认保持折叠，只保留公司、当前政策类型、双账期说明和明确的展开按钮。
- 用户点击“展开政策参数”后，才显示费率、基数、特殊费用、缴费规则和配置来源。
- 社会保险与住房公积金页签切换后，政策参数恢复默认折叠，避免长期占用确认表的首屏空间。
- 折叠控件必须使用原生按钮、`aria-expanded` 和 `aria-controls`，不能只依赖点击卡片或颜色表达状态。
- 确认表只能保留一个标题。标题、只读说明、账期人数摘要、刷新和打印操作必须合并在同一个确认表头中。
- 禁止在确认表工具栏和表格上方重复显示“社会保险确认表”或“住房公积金确认表”。
- 该规则同时适用于社会保险和住房公积金，不能只修复一个页签。
- 折叠和合并仅改变信息层级，不改变费率、基数、缴费月份、配置来源、确认状态或打印数据。

## 6. 动态视口表格与合计行

八个业务页签的当前活动表格必须按浏览器实际剩余高度动态贴底，不能继续以固定 `62vh` 或 `32vh` 作为最终高度。

- 表格目标高度为：可见视口底部减去当前表格顶部坐标，再减去 10px 底部安全间距。
- 只调整当前可见页签、当前可见视图中的 `.jz-table-box`，不能同时修改隐藏表格。
- 页签切换、账期切换、数据加载、考勤视图切换、政策参数展开收起、窗口缩放和 Desk 页面再次显示时必须重新计算。
- 高度计算使用双 `requestAnimationFrame()`，让布局先稳定，再读取表格顶部坐标。
- 表格内部继续承担纵向和横向滚动，页面外层不能因表格固定高度产生不可达区域。
- 社会保险与住房公积金确认表不得保留独立的 `32vh` 高度上限。
- 所有财务明细表必须保留底部合计行。个人所得税表必须动态汇总应发薪资、免征额、个人社保、公积金、专项附加扣除、当月个税和实发工资。
- 动态高度仅改变容器几何尺寸，不改变任何工资、税费、社保、公积金或现金数据。

## 7. UI 边界

- 不新增 inline `style=`。
- 不使用装饰 Emoji。
- 不使用彩色药丸展示普通金额、数量或姓名。
- 一个页面状态只保留一个高强调 Primary。
- 完整档案编辑继续使用现有“编辑档案”入口。
- 参数调整弹窗只修改勾选员工的一个参数。

## 员工档案双通道修改与表头滚轮横向滚动标准 (2026-10-12 用户强制标准)
> **全局表格与档案交互铁律**：所有员工信息模块与大宽表必须无条件遵守以下交互规范，严禁后续改动回退。

### 1. 修改前提（未确认即允许修改）
* **前提 1**：只要当前账期的员工信息**尚未点击确认放行**（未锁定，即 `!is_confirmed`），则员工的所有档案信息**均可随时修改**；
* 若当前账期已确认放行或月度已封账，则进入只读受控状态，点击时友好提示：“本账期员工档案已确认并处于只读受控状态；如需修改，请先取消确认”。

### 2. 修改的双通道触发方式
* **方式 1（整行点击直达）**：鼠标悬停在员工行上呈现手型光标（`.jz-row-clickable` / `.qifu-row-clickable` / `.ashan-row-clickable`），点击该员工行的任意信息区域（除左侧勾选复选框与右侧操作按钮外），**直接弹出该员工的修改界面**；
* **方式 2（最右侧操作按钮）**：点击该行最右侧【操作】列中的【编辑档案 / 修改】按钮，同样**弹出该员工的修改界面**；
* **左侧复选框独立**：点击序号左侧的复选框（或复选框单元格）仅切换人员勾选状态，用于批量参数调整或批量离职，与整行点击修改互不干扰。

### 3. 标题行鼠标滚轮左右横向滚动（全局所有表格通用）
* **表头滚轮转横向滚动（Mousewheel-to-Horizontal Scroll）**：当鼠标光标悬停在任何表格的**标题行（`thead`）**或顶部辅助滚动条上拨动滚轮时，若表格存在横向溢出（`scrollWidth > clientWidth`），系统自动拦截默认垂直滚动，将滚轮增量（`deltaY`）平滑转换为表格容器的**左右横向滚动（`scrollLeft += deltaY`）**；
* **表体保持纵向滚动**：当鼠标位于表格内容区（`tbody`）时，滚轮保持默认的上下垂直滚动，实现“表头滚轮左右看列、表体滚轮上下看行”的高效人机工程体验。

### 4. 明细表格多选模式与行点击双态交互铁律 (2026-10-12 用户强制标准)
* **未多选状态（已勾选人数 = 0）**：
  * 点击任意员工行（除最右侧操作按钮外）：直接调起该员工的档案修改弹窗（极速编辑模式）；
  * 点击最右侧【操作】列中的【编辑档案 / 修改】按钮：调起该员工的档案修改弹窗。
* **多选状态（已勾选人数 > 0 / 多选模式激活）**：
  * **点击任意行不再弹出编辑弹窗，而是切换该行的勾选状态（选择 / 取消选择）**！便于连续批量选定人员；
  * 如果在多选模式下需要编辑单个员工，必须点击最右侧【操作】列中的按钮，或者取消所有勾选恢复单选编辑模式；
  * 勾选状态下的行以 `.jz-row-selected` / `.qifu-row-selected` 全行背景微蓝高亮反馈（`#eff6ff`）。

### 5. 社保与公积金动态基数差异化计算重构标准 (2026-10-12 用户强制重构)
* **社保动态基数**：
  * 选项名称：`动态基数(税前工资20%)`；
  * 计算法则：`社保基数 = 税前工资 × 20%`。
* **公积金动态基数**：
  * 选项名称：`动态基数(税前工资5%)`；
  * 计算法则：联动当前企业配置的公积金公司缴费比例（当前设定：公司 `5%`、个人 `5%`），`公积金基数 = 税前工资 × 5%`（严禁与社保混用 20%）。
