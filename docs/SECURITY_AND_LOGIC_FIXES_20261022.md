# Security and logic fixes — 2026-10-22

This revision addresses concrete conflicts found between workbench code, authorization policy and package documentation.

## Fixed

- Payroll bootstrap no longer calls a company-mandatory helper before a company exists.
- Boss payroll upload now binds the write check to its selected company.
- Monthly invoice-closing read/lock/unlock operations now enforce Company scope.
- Invoice-closing SQL stats require relevant standard DocType read permissions.
- Month end uses the actual calendar last day instead of a synthetic `YYYY-MM-31` value.
- Wire-transfer SQL read models are filtered through standard Purchase Invoice permissions.
- Wire-transfer document creation/submission no longer relies on broad `ignore_permissions=True` flags for Supplier, UOM, Item, Purchase Receipt, Purchase Invoice, Stock Entry, Reimbursement Request or Payment Entry.
- Wire-transfer invoice-number duplication now uses the same global active-invoice rule as normal Purchase Invoice validation.
- Wire-transfer official-invoice completion checks Purchase Invoice write permission, monthly closing, duplicate invoice number and tax-invoice re-matching before/after the submitted metadata patch.
- Saving a wire-transfer bundle as draft no longer submits its Reimbursement Request behind the user's back.
- Wire-transfer lifecycle documentation and server state now match the current two-state UI (`draft` / `completed`).
- Purchase Invoice custom tax calculation now converts base amounts using `conversion_rate` and no longer overwrites `outstanding_amount` during validation.
- Reimbursement bundle deletion no longer cancels/deletes unrelated source Purchase Invoices or Purchase Receipts. Cascade deletion is limited to documents explicitly generated by the `现金报销` flow and still requires standard permissions.
- Canonical reimbursement stale-reservation cleanup no longer uses raw SQL DELETE.
- Added a single `AGENTS.md` governance source and updated reimbursement documentation to reflect the actual split between domain service and workbench adapter.
- Added a per-user table title/percentage-width API without changing current table UI by default.

## Intentionally not changed

- Existing table columns, row content, page visual styling and business field order remain unchanged unless a user saves table-column overrides through the new API.
- Legacy `fixtures/custom_html_block.*` mission-control assets are removed. `setup.after_migrate()` also deletes the app-owned legacy Custom HTML Block record if it still exists in an upgraded site.
- Live ERPNext database behavior and browser rendering require deployment-site regression testing; static checks cannot replace that step.
