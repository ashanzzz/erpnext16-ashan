# 各业务模块 UI 和交互规范

## 采购
Material Request、Purchase Order、Purchase Receipt、Purchase Invoice、Payment Entry 等标准单据完整编辑继续使用 ERPNext Form。

采购 Workbench 负责：
- 候选池
- 批量选择
- 上下游关系
- 数量金额核对
- 生成下游单据
- 异常处理

先复用 `procurement_workbench.js/css`，不要重新实现完整标准单据编辑器。

权限使用标准 DocPerm/`frappe.has_permission()`。UI 从服务端 capability 决定动作可见性。company 服务端验证。

## 报销
`Reimbursement Request` 已有 Form JS、List JS 和服务端 service。
单据自身生命周期优先标准 Form。批量审核、汇总和跨单据关联才用 Workbench。
禁止平行创建第二套 Reimbursement 模型。

### 祺富人事薪酬工作台 (desk/qifu-hr-salary-workbench) 专属工规铁律 (2026-10-27 核心标准)
1. **车间外部实发工资强制整元取整铁律 (ROUND(..., 0))**：
   - 车间外部发薪表是工人现场发薪、打卡发放的实发净额凭证。必须在分项（天工、工时、全勤、加班、达标、职位补贴、房/车补、扣除）未取整加总后，严格执行一次性 `=ROUND(..., 0)` 强制四舍五入取整到整数元（例如张引弟 $5843.55 + 530.84 = 6374.39 \to 6374$ 元整）；
   - 严禁把车间半成品提前取整的整数（如 5844）直接去加带小数的补贴（如 230.84），从而错误拼凑出 6374.84 元导致向上误进位 6375 元。必须加总未取整分项后统一取整；
   - 个税 7 级累进预扣 VBA 闭式倒推引擎必须严格以四舍五入后的整数目标工资（如 6374.00 元）作为 `target_net` 反推税前工资（6405.45 元）与应扣个税（31.45 元），确保全表与会计 Excel 100% 绝对一致（0.00 元误差）。
2. **车间外部实发表与固定薪资人员绝对物理隔离与明细弹窗纯净化**：
   - 彻底移除“应发金额”列：车间外部实发表（Tab 2）只承载到手实发净额，表头与表体彻底移除“应发金额”列，只保留四舍五入整数的【实发金额】。企业法定综合税前应发工资必须且只能在 Tab 5（个税 68 列大宽表）与 Tab 6（综合记账结算）中进行全员法定汇算；
   - 明细弹窗纯净还原，严禁下游扣税污染：外部实发表点击【查看】弹出的行明细弹窗，唯一职责是纯粹还原与呈现车间发薪原始凭证的解析过程与核对依据（工时考勤明细、津贴补贴、请假合规核验、车间实发整元加总、导入溯源快照）。严禁混入任何下游的“税前应发工资(倒推)”、“社保代扣”、“公积金代扣”、“预扣个税”等异构数据，恪守外部发薪凭证原貌；
   - 固定薪资人员绝不写入外部实发表：凡薪资模式包含“固定”（如 `税前固定工资`、`税后固定工资`、`不税固定工资`），或档案中设定了固定工资（`fixed_salary > 0`）的人员（如外籍管理人员 UNURBAYARENKHZUL），一律从外部实发主表及相关车间发薪明细中彻底过滤排除，绝对不写进外部实发表格；
   - 未上传车间实发 Excel 时，外部实发表纯净呈现“待上传”引导面板，严禁拿母表固定工资人员来伪装填补车间实发表。固定薪资人员仅在全员母表底册（Tab 1）、个税大宽表（Tab 5）、综合记账结算（Tab 6）中按全员用工成本参与法定综合汇算。
3. **员工在册档案动态账期时间窗口联动与离职人员排除**：
   - 自动排除往期已离职人员：员工档案底册（Tab 1）默认在册全员必须严格与当前选定账期月份动态联动：`relieving_date < 当前月份第一天`（往期已离职人员，如 7 月底离职的霍清海在 8 月）以及未来入职人员，在默认“全部人员”在册名单及核定确认弹窗、导出中自动排除（8 月份在册人数精准为 25 人，往期离职人员绝不出现）；
   - 当月离职黄色高亮：离职日期落在当前选定账期月份内的人员，在当月列表呈现，行背景标记为柔和黄色高亮（`.qifu-row-resigned-cur` / `var(--ashan-color-amber-50)`，`#fffbeb`），状态列明确标注为“当月离职”；
   - 当月新入职绿色高亮：入职日期落在当前选定账期月份内的人员，在当月列表呈现，行背景标记为柔和绿色高亮（`.qifu-row-newcomer` / `var(--ashan-color-green-50)`，`#f0fdf4`），状态列明确标注为“当月新入职”；
   - 已离职按需穿透分段：在 Tab 1 分段控件中增加“已离职”选项（`data-type="history_resigned"`），专员可在未来随时穿透查阅包含往期已离职在内的全部历史离职人员。
4. **全工作台按钮生命周期设计与色彩语义绝对统一**：
   - 阶段核定确认：各工作台与页签阶段确认按钮，文案统一为【确认本表】，颜色统一为标准深绿（`.btn-success.qifu-btn-confirm`，背景色 `#15803d`）；
   - 阶段核定撤销：阶段核定生效后，按钮自动转为【撤销本表】，颜色统一为标准深红（`.btn-danger.qifu-btn-stage-cancel`，背景色 `#b91c1c`）；点击后弹出提示确认，撤销后恢复可编辑修改状态；
   - 封账锁定：整体月度封账后，各阶段确认按钮统一转为中性禁用灰（`.btn-default` disabled，文案【已封账锁定】）；
   - 主流程操作（上传原件/申报表）：统一采用品牌主色蓝（`.btn-primary.jz-btn-blue`，背景色 `#2563eb`）；
   - 配置与辅助工具（基数设置、导出、打印）：统一采用次级中性线框（`.btn-default.ashan-btn-secondary`）；
   - 危险清理（删除凭证/申报表）：统一采用次级危险线框（`.ashan-btn-danger-outline`，悬浮微红）。
5. **社保与公积金集中基数设置与表格行内空按钮彻底删除**：
   - 表格行内零空按钮原则：彻底删除社会保险（Tab 3）与住房公积金（Tab 4）数据行基数单元格内无文字、无图标的空修改按钮（`<button class="btn-edit-contribution-base"></button>`），基数列纯净靠右展示数字，杜绝视觉噪点；
   - 工具栏独立【基数设置】通道：在社会保险工具栏与住房公积金工具栏分别常驻【基数设置】次级线框按钮，分别打开独立的年度社保缴费比例/基数与公积金缴存比例/基数设置弹窗，集中维护最低缴费基数、单位与个人费率、大额医疗救助金标准等核心参数；
   - 历史封账快照不可篡改保护：已核定锁定或封账的历史月份启动只读快照保护（`locked_snapshot = True`），全局参数变更仅自动联动当前未封账账期（如 2026-08），绝不静默篡改已出具完税凭证的历史账期。

6. **车间外部实发表（Tab 2）三大核心指标与原表勾稽业务规范 (2026-10-27 用户强制铁律)**：
   - **卡片 1：【发放总金额】**：全员税后实发到手总金额（整元四舍五入），严格等于“考勤部分总金额 + 补贴总金额”（例如 2026-09 账期为 `139,394` 元，2026-08 账期为 `142,126` 元）；
   - **卡片 2：【考勤部分总金额】**：车间实发表（上半部）所有 23 位工人“实发工资”列的权威合计（保留一位小数，例如 2026-09 账期为 `125,409.0` 元，2026-08 账期为 `127,945.0` 元）。必须包含正常工时绩效人员、孟祥山计件承包（8,732元）、翟风杰车间调整（全勤100 + 调整6,400 = 6,500元）、李金刚加班含餐补（405元）等特殊人员。**严禁仅加总工时分项而遗漏车间调整和包干实发！**；
   - **卡片 3：【补贴总金额】**：车间实发表下半部补贴表（职位补贴 + 房/车补）的纯净总计（四舍五入整元，例如 2026-09 账期为 `13,985` 元，明细为职位补贴 10,354.67 + 房车补 3,630.00；2026-08 账期为 `14,181` 元，明细为职位补贴 10,430.84 + 房车补 3,750.00）；
   - **三大指标闭式守恒方程**：
     $$\text{考勤部分总金额 (125,409.0)} + \text{补贴总金额 (13,985)} = \mathbf{发放总金额 (139,394)}$$
   - **历史问题根因与 AI 继承防坑指南**：
     - 此前系统显示 132,587 / 118,602 / 13,984.67 的根本原因：翟风杰车间实发 6,500 元（含 100 全勤 + 6,400 调整），系统此前只取全勤 100 元，漏算 6,400 元；李金刚加班费 525 元中含 405 元餐补（27天 × 15元），系统导入时拆出餐补但在考勤计算中漏加，漏算 405 元；两项漏算合计 6,400 + 405 + 2元舍入微差 = 6,807 元。导致系统实发仅显示 132,587 元（139,394 - 6,807），考勤仅显示 118,602 元（125,409 - 6,807）。
     - 今后任何 AI 无论在导入解析还是后台异步重算时，**必须将外部实发表的【实发工资】（`workshop_net`）作为车间计薪的最高权威源**，分项与总额的差额自动记入 `salary_adjustment`，确保任何重算和个税倒推都不会丢失这 6,807 元，永远守恒！

## 合规、环保、特种设备
页面核心是主体/设备、当前状态、到期日期、剩余时间、缺失材料、待办、证据、历史。

已有 daily scheduler 刷新相关状态时，前端不再创建另一套权威到期算法。

## 物业和租赁
Workbench 聚焦账期、合同、费用、应付实付、凭证和结算状态。
标准 Contract/DocType 的详细编辑继续 Form。

## 税局发票和 AI 匹配
必须展示：
- 源票据
- 推荐对象
- 匹配分数/置信度
- 匹配依据
- 冲突
- 候选项
- 当前状态
- 用户决定

用户确认后，服务端重新读取目标并验证权限、company、状态、金额/数量、是否已被其他操作关联。

AI 推荐不能直接绕过 ERPNext lifecycle。

## 月结和封账
页面必须突出 company、账期、锁定状态、未完成前置条件、影响范围、操作人、时间和解锁原因。

封账/解锁按钮由服务端 capability 决定。确认弹窗说明影响对象。

## Workspace/Dashboard
Workspace 用于导航和需要关注的事项。
优先 2 到 4 个真正可行动指标、待办、异常、快捷入口。
不要固定每个模块 6 到 12 张彩色 KPI 卡。

## 统一的边界
统一的是颜色语义、按钮层级、金额数量格式、表格扫描、Dialog 行为、异步状态和权限反馈。

不要求所有模块相同 KPI 数量、冻结列、Tab、Dialog 宽度或表头层数。


## 普通表格界面四段式标准化架构 (Four-Tier Architecture Standard)
全系统普通表格界面一律拆分为固定的四大物理段，各司其职，绝不混杂：
1. **第一段：大标题**：顶部纯净大标题（标题 + 简述），背景透明，绝不加白底和边框“圈起来”；
2. **第二段：筛选行**：单据状态分段点选与检索输入框（单号/供应商/物料/经手人）；
3. **第三段：功能行 (Action Bar)**：
   - 左侧：视图切换（单号/明细）、已选统计胶囊、本次总计金额、表格视图胶囊（X/X 列 · X% · 标准）；
   - 右侧：全选本页、清空选择、删除单据/撤单、刷新、生成下游单据、新建单据、`☷ 列设置`；
4. **第四段：表格**：纯净独立大宽表卡片，内部不塞任何工具栏，单行表头，全闭合列竖线，末行一体化 tfoot 投影平账。
