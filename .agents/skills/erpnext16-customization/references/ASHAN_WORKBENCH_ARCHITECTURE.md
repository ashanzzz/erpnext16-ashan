# Ashan 统一工作台架构与性能纪律

## 1. 目标与边界

所有 `ashan_cn_procurement` 自定义模块向同一种工作台体验靠拢：严肃、低噪、高信息密度、可恢复、快速响应。统一带来更低的重复代码、更一致的操作习惯和更稳定的体感速度；它不是把所有业务做成相同的单据流程。

**统一工作台框架，保留业务适配层。**

| 统一层 | 每个模块保留的适配层 |
| --- | --- |
| 页面骨架、筛选栏、KPI、宽表、空态与加载态 | 数据集合、服务端查询和排序 |
| 共享 CSS 令牌、按钮、状态、金额、弹窗、建议浮层 | 模块角色、公司范围与权限判断 |
| 自动恢复、草稿提示、关闭保护、局部刷新 | 草稿是否允许、封账/审核/作废状态机 |
| 列宽语义、表头、冻结、横向滚动与可访问文案 | PO、PR、PI、RR 等单据链及法定计算 |
| 性能规则、请求生命周期、浏览器验收 | 财务、库存、税务与薪酬的服务端复核 |

任何模块都不能因为使用同一 UI，而放松角色、公司、状态或业务事实校验。

## 2. 标准工作台骨架

每个新模块或完成迁移的模块，都以如下可配置骨架组织：

1. **页面上下文**：公司、期间、权限、当前视图和可用操作。
2. **控制栏**：统一高度、清晰筛选、分段控件与一个明确主操作。
3. **摘要区**：仅显示能支持当前决策的 KPI；不为装饰堆卡片。
4. **数据区**：单层复合表头、语义列宽、冻结标识列、总计、空态与错误态。
5. **工作弹窗**：静态背景、顶部和底部双出口、自动恢复、局部计算、明确提交。
6. **业务适配器**：页面只调用模块公开的查询、创建、草稿、作废/审批等能力；服务端仍负责权限、公司范围、状态和 Document 复核。

共享实现的入口优先是 `ashan_ui_kit.css` 与 `AshanUI`。页面可声明自己的字段、列、动作和数据源，但不复制整段 CSS、表格骨架、自动保存或事件处理逻辑。

## 3. 组件与交互统一契约

必须统一的组件包括：

- 筛选和期间控件、KPI 卡片、空态、错误态、加载态；
- 金额/数量显示、状态标签、文件标签、危险操作确认；
- 大宽表、顶部同步横向滚动、冻结标识列、底部合计；
- 分段控件、企业级建议浮层、已选实体胶囊；
- 静态弹窗、功能性 `✕`、底部关闭/取消、自动恢复提示；
- 本地录入行的增加、移除、撤销与局部合计。

用户可见文案延续 Ashan 规范：纯中文、无装饰性 Emoji、标题只表达一个业务概念、规格展示为“规格”、备注展示为“备注”或“用途说明”。

草稿、编辑、删除不属于通用按钮行为。先由业务适配器声明该模块处于“本地录入、服务器草稿、已提交链路”中的哪一层，再按 `TRANSACTION_PICKER_LIFECYCLE.md` 执行对应动作。

## 4. 轻量性能纪律

### 浏览器与渲染

- 首屏只请求工作台所需的上下文、摘要和当前页列表；详情、附件、关联链路和大明细在用户明确查看时加载。
- 筛选与搜索使用防抖；刷新只更新受影响的 KPI、行或局部区域，避免输入时重绘整个页面、关闭重开弹窗或抢走焦点。
- 事件使用页面作用域或事件委托，并在 Frappe SPA 页面重新进入/销毁时解除旧绑定、清理定时器和未完成请求，防止重复点击、内存泄漏与请求叠加。
- 宽表采用服务端排序、筛选和分页；只有真实数据量与性能证据表明需要时，才引入虚拟滚动。不要预先为小列表增加复杂度。
- 复用公共 CSS/JS；不为统一 UI 额外引入 React、Vue 或其他大型运行时，也不一次加载所有模块的业务代码。

### 服务端与网络

- 每个读取接口仅返回当前视图需要的字段，明确排序，并在服务端执行公司范围、角色和业务状态过滤。
- 创建、提交、作废、删除、导入、封账等请求使用 POST；提交前服务端重载并校验 Document，而不是相信页面缓存。
- 同一个用户动作只发起一条可识别请求。对慢请求展示稳定的进行中状态，禁止按钮连点产生重复单据。
- 性能是否改善必须以真实网络请求、浏览器控制台、渲染响应和业务结果验证；不以固定人数、固定金额或主观感觉代替事实。

## 5. 渐进迁移方式

不要同时重写所有页面。按以下顺序逐块迁移，每一块保持现有接口、权限与业务结果不变：

1. 先抽取无业务风险的视觉令牌、按钮、状态、金额、空态和弹窗外壳。
2. 再统一筛选栏、KPI、宽表、列定义与局部刷新方式。
3. 提取自动恢复、建议浮层、行编辑和危险操作确认等交互契约。
4. 最后才按模块接入各自的草稿、编辑、作废、审批和单据链适配器。

每次只选择一个可视觉验收的工作台或功能区。运行 UI 治理检查、目标模块服务端测试、真实浏览器交互和控制台检查后，再迁移下一块。禁止借“统一架构”重写数千行页面并同时改变财务业务逻辑。

## 6. 完成标准

一个模块接入统一工作台后，应同时满足：

1. 公共视觉和交互来自共享组件，新代码不增加 HTML `style=` 或重复设计令牌。
2. 页面在正常进入、重复进入和切换公司/期间后，不出现重复事件、残留弹窗、重复请求或内存增长迹象。
3. 搜索、筛选、保存和局部更新不触发无必要的整页刷新；详情按需加载。
4. 宽表、弹窗、草稿保护和危险操作均符合本知识包的 UX 与生命周期规范。
5. 模块的数据集合、权限、公司范围、法定计算、单据链和状态机仍由自己的业务适配器与服务端验证，不被 UI 框架绕过。

## 7. 小型制造企业的采购岗位工作台

对于约 40 人的制造企业，采购流程采用“一个共享流程内核 + 三个岗位工作台 + 一个主管总览”，不复制三套前后端逻辑：

- `物料申请`：申请人员登记物料、规格、数量、参考单价、预估金额与备注，查看后续进度。
- `采购执行`：采购人员处理采购订货、发票登记与付款报销发起。
- `收货入库`：仓库人员只核对订购数量、累计已收、本次实收、未收数量、单价和金额。
- `采购总览`：管理人员查看申请、采购、收货、发票、付款报销全流程；普通操作人员不以此页作为日常入口。

四个页面标题统一使用四个中文字，不使用装饰性 Emoji。岗位入口由 Page、侧边栏和服务端能力三层共同限制；一个用户可兼任多个岗位，但具体创建、编辑、删除、提交仍须根据 DocType 权限、公司范围和单据状态动态判定。

默认字段坚持小企业适用的最小充分原则：重点追踪物料、规格、数量、单价、金额、发票号码、已付/待付金额与备注。收货环节默认不新增批次、独立收货备注、质检附件或复杂验收模型；只有实际存在批次管理、法定追溯或质量检验需求时才按业务事实启用。页面外壳、表格、弹窗和服务端查询共用；每个岗位只请求本页 KPI 与当前阶段数据，避免隐藏加载完整五阶段数据。

## 8. 库存收发存与物料全景穿透中枢标准

1. **闭式守恒与四段结转架构**：
   - 首行显式呈现【上期结转 (期初)】；
   - 中间行按记账时间倒序呈现流水；
   - 末尾行显式呈现【本期发生合计与期末结余 (实物守恒平账)】（`期初 + 累计入库 - 累计出库 = 期末结余`）；
   - 结存数量强带法定计量单位（如 `72.00 Nos`）；
   - 出入库纯净二元化（【入库数量】与【出库数量】两列）。
2. **零抖动局部微更新与期间快捷点选**：
   - 弹窗内置期间胶囊（本月至今/近3月/近半年/今年/自定义）；
   - 筛选切换时只微量更新 `tbody`/`tfoot`，零整页刷新与抖动。
3. **入库单 vs 出库单精准区分穿透**：
   - 入库单明细（`Purchase Receipt` / `Purchase Invoice`）：展示供应商、收货目标仓库与 `+XX.00` 绿色入库；
   - 出库单明细（`Stock Entry - Issue` / `Delivery Note`）：展示出库发货仓库、领料人/用途说明与 `-XX.00` 琥珀色出库。
4. **原位极速出库与直接过账提交**：
   - 弹窗顶部与底部均常驻【快捷出库】；
   - 自动预填物料、当前仓库账面可用库存与发货仓；
   - 默认直接过账提交（`submit_direct = 1` ☑），提交即生成生效单据并扣减库存；
   - 弹窗与台账无感局部追加流水并实时重算结余。
5. **GPU 硬件合成层与零掉帧流畅度**：
   - 保持 100% 视觉特效（磨砂玻璃、渐变、阴影）；
   - 为遮罩与弹窗配置 `contain: strict; will-change: opacity, transform; transform: translate3d(0, 0, 0);`，由独立显卡硬件插值计算；
   - 使用 `requestAnimationFrame` 解耦开窗动画帧与数据请求/DOM 构建，确保 60fps/120fps 满帧丝滑。
