# 验证、迁移与交付闭环

## 1. 完成的定义

“已修改文件”不是完成。任何功能变更必须给出与风险匹配的实际证据：代码检查、迁移结果、业务关键路径、浏览器控制台/网络和视觉检查。

## 2. 本项目标准流程

1. 读取当前 `AGENTS.md`、业务规则和目标 Controller。
2. 仅改动用户授权范围内的 custom app / 文档 / 测试。
3. Python 逻辑做静态语法检查；前端执行 `python scripts/verify_ui_style_governance.py`，其基线只允许下降，不允许提高来绕过问题。
4. 使用 `python scripts/sync_and_migrate.py` 热同步并迁移。
5. 若输出出现 `bench_migrate.lock`、`LockTimeoutError` 或 Traceback，先只读确认无迁移进程；只删除已确认孤立的单一锁；随后手动运行目标站点 migrate，以退出码 `0` 为准。
6. 编写/运行 Playwright 验收：真实登录 Desk，操作页面、弹窗、导入/导出、状态和权限；检查控制台、网络和全景截图。
7. 报告实现范围、验证证据、已知限制和需要人工批准的后续操作。

## 3. 必测内容

| 改动类型 | 最少验证 |
| --- | --- |
| Python 服务/API | 输入校验、角色、公司范围、状态、错误路径、排序/汇总 |
| 财务/库存/薪酬 | 正常、零值、特殊人员/边界期间、重复提交、封账/解锁、原始凭证 |
| UI/交互 | 宽/窄视口、空/加载/错误态、弹窗关闭与草稿恢复、键盘、横向表格、控制台 |
| 权限 | 管理员、操作员、无关通用角色、不同公司范围、直接 RPC 调用 |
| 迁移 | 同步脚本、真实 migrate 退出码、资产版本加载、关键路径无回归 |

## 3.1 Desk SPA 回访防白屏验收

任何 custom Desk Page 或共享工作台资产变更，除冷启动直达 URL 外，还必须在同一登录 Desk 会话中验证：`页面 A → 页面 B → 返回页面 A`。返回后断言 A 的标题、主容器和关键表格/表单可见，并检查新增业务 Console error。

- 验收定位器必须按当前工作台容器或 `data-workbench` 属性限定；Desk 会保留隐藏页面，因此全局 ID 定位器可能命中多个旧页面，不能作为通过证据。
- 同时检查实际加载的 JS/CSS 资源 URL；页面运行时资源由 Frappe 追加版本，不把手工 `?v=` 拼回 `frappe.require()`。
- Socket.IO `Invalid origin` 是反向代理 Host/Origin 独立问题；记录但不与页面初始化错误混为一类。

## 4. 浏览器证据标准

- 浏览器加载的 CSS / JS 查询版本与源码改动一致。
- 不出现新增 Console error；网络请求有符合预期的成功/拒绝语义。
- 菜单入口和服务端权限同时生效：隐藏菜单并不算通过。
- IP 访问若出现 Socket.IO `Invalid origin` 或回首页，单独核验反向代理 Host/Origin；不要把它误判为业务页面失败或成功。

## 5. 本技能自身更新

这是文档型插件，不会改变 ERPNext 站点。因此更新本插件的最小验证是：插件结构校验、Markdown 链接/引用检查、敏感信息扫描，以及在新智能体会话中执行一个代表性提示词。无需对本插件运行 ERPNext 迁移。
