# 知识包变更记录

## 1.8.0 — 2026-08-27

- **固化库存收发存台账与物料全景穿透标准**：
  - 闭式守恒四段结转：首行显式呈现【上期结转 (期初)】，中间行倒序排列当期流水，末尾行呈现【本期发生合计与期末结余 (实物守恒平账)】（`期初 + 累计入库 - 累计出库 = 期末结余`）。
  - 结存数量强带法定主计量单位（如 `72.00 Nos`）；出入库列头纯净化为【入库数量】与【出库数量】两列。
  - 弹窗内置期间快捷点选（本月至今/近3月/近半年/今年/自定义），筛选切换采用零抖动局部微更新（In-Place Micro-Update）。
- **固化入库单 vs 出库单定制化穿透预览引擎**：
  - 严格区分业务流向：入库单明细呈现供货供应商、收货目标仓与 `+XX.00` 绿色正向入库；出库单明细呈现出库发货仓、领用用途与 `-XX.00` 琥珀色负向出库；严禁把入库单目标仓误标为发货仓。
- **固化原位极速出库直接过账引擎**：
  - 在全景流水弹窗顶部与底部结余行常驻【快捷出库】入口，智能预填物料、当前仓库结存与发货仓。
  - 默认启用【`直接过账提交 (立即生效并扣减库存)`】（`default: 1` ☑），提交即调用 `doc.submit()` 生成已生效单据并实时扣减库存，零整页刷新。
- **固化零降级 UI 特效深度性能优化标准**：
  - 严禁为了“性能”而削减磨砂玻璃模糊（`backdrop-filter: blur`）、渐变与阴影特效。
  - 引入 CSS GPU 硬件合成层（`contain: strict; will-change: opacity, transform; transform: translate3d(0, 0, 0);`）由显卡硬件插值计算，彻底消除 CPU 软件光栅化逐帧重绘（Paint Thrashing）。
  - 引入 `requestAnimationFrame` 解耦开窗动画与数据/DOM 渲染，确保 60fps/120fps 满帧丝滑。
- **固化弹窗显式双重安全退出通道**：
  - 静态背景防误触（`backdrop: "static"`），右上角注入醒目 `✕` 关闭按钮（悬浮微红），底部操作栏显式配置【`✕ 取消`】次级按钮。

## 1.7.0 — 2026-08-26

- 固化已实机确认的高效紧凑 UI 风格：系统字体栈、清晰字号梯度、`1px` 中性边框、轻量蓝色激活反馈和克制阴影。
- 新增“紧凑双行选择卡”规则，用于需要解释差异的 2～4 个互斥模式；简单短选项继续使用普通分段胶囊，避免卡片滥用。
- 明确动态显隐与稳定布局：只有选中例外模式后才显示依赖字段，说明区域保持稳定，避免操作区跳动。
- 明确身份导航与业务上下文入口分离：保留 Frappe 原生用户菜单，公司、期间和业务日期使用独立紧凑入口。

## 1.6.2 — 2026-08-25

- 新增 Frappe Desk 缓存式 SPA 防白屏规则：`on_page_load` 首次挂载、`on_page_show` 恢复缓存实例；实例和 DOM 查询必须收敛到各自 wrapper，禁止全局重复 ID 串页。
- 验收增加同会话 `A → B → A` 回访；冷启动 URL 正常不再视为工作台白屏问题已验证。
- 明确资源恢复边界：优先定位生命周期与已加载资产；自定义 app 只做 app 级 build、缓存失效与重启，不重置 Frappe/ERPNext 核心资产。

## 1.6.1 — 2026-08-25

- 记录 Frappe 16 页面懒加载白屏经验：`frappe.require()` 的非 bundle JS/CSS 路径不手工拼 `?v=`，由框架自动追加资源版本。
- 区分 `hooks.py` 直接注入资源的查询版本与页面运行时懒加载路径，避免错误复用缓存策略。

## 1.6.0 — 2026-08-24

- 新增小型制造企业采购岗位工作台规范：共享流程内核下使用“物料申请、采购执行、收货入库、采购总览”四字入口。
- 固化采购页面最小充分字段：物料、规格、数量、单价、金额、发票、付款报销和备注；默认不引入批次、独立收货备注或复杂质检字段。
- 明确岗位入口、页面可见性与服务端能力三层收口，并要求每页只加载自身 KPI 和当前阶段数据。

## 1.5.0 — 2026-08-24

- 明确互斥状态筛选的点标语义：`🟡` 仅表示待办，`🟢` 仅表示已完成，且必须与完整中文状态文字同时出现。
- 明确“全部 / 汇总 / 不限”使用中性纯文字，禁止以 `🌐` 表达“全部”，避免把地域/网络语义误用于聚合筛选。

## 1.4.0 — 2026-08-24

- 新增 `ASHAN_WORKBENCH_ARCHITECTURE.md`，确认全部 Ashan 自定义模块采用“统一工作台框架 + 业务适配层”的长期方向。
- 固化共享范围：页面骨架、组件、自动恢复、表格、人机工效和轻量性能策略；保留范围：财务/库存单据链、权限、状态机、法定逻辑与数据集合。
- 规定渐进式提取、按需请求、局部刷新、SPA 生命周期清理和不引入无必要前端大框架的性能纪律。

## 1.3.0 — 2026-08-24

- 新增 `TRANSACTION_PICKER_LIFECYCLE.md`，根据报销、月结入库、自办电汇三个工作台的实际代码基线，明确本地行、服务器草稿和已提交财务/库存单据链不能混用“编辑/删除”语义。
- 将草稿置顶、原位编辑、危险级联动作的审计确认、即时过账创建器的本地恢复草稿、字段标题与列宽整改要求纳入共享 UI 系统。
- 记录当前三页的统一点与差异：报销已有静态弹窗和草稿排序；月结、电汇目前是即时过账创建器，不应仅为了表面一致性而提前建立正式单据链。

## 1.2.0 — 2026-08-24

- 新增 `PERSONALIZED_UI_CHARTER.md`，将报销申请中心的个人 UI 取舍固化为可迁移规则：纯中文且不含装饰性 Emoji、字段标题不以斜杠混称、流式不折行分段控件、双通道安全退出与全生命周期草稿保护。

- 主技能与 UI 系统增加该宪章的读取入口，避免后续 ERPNext 页面改造遗漏个人化交互标准。

## 1.1.0 — 2026-08-24

- 增加系统推导/人工例外/草稿差异的数据来源视觉语义，以及上传—删除—恢复的单入口生命周期。

## 更新规则

- 每条长期规则变动均记录日期、修改原因和影响的参考文件。
- API / 链接的版本性调整记录在此处；不记录真实业务数据、客户信息、凭据或瞬时任务内容。
- 重大风格变动在跨智能体发布前，应在 ERPNext Desk 中完成一次代表性页面的视觉和交互验收。
